# 「青蓝」软件质量保证与测试实验工作台（泰山新松队项目）

> 面向《软件质量保证与测试：原理、技术与实践》的课程实验与多题型自测平台。
> 一条虚构的人才服务业务线，8 个可操作实验 + 48 道单选/多选/填空随堂题库，从代码审查一直走到发布质量门禁。

---

## 1. 项目定位

这不是教材摘要网页，也不是答题页面。它把课程中的 8 个核心知识点做成**可操作、可复算、可验证**的实验：

**理解知识 → 设置条件 → 设计测试 → 执行观察 → 比较预期与实际 → 验证结论 → 形成测试证据**

所有实验共用一条业务线：虚构平台「青蓝人才服务平台」的**培训报名与认定预约**业务。
同一套业务规则（费用计算、资格审核、报名单状态机）被不同测试视角反复使用，学生因此在第 8 个实验里能真正用上前 7 个实验产生的证据。

**业务场景为本项目原创教学案例**，不声称任何企业合作、真实上线或真实用户数据；不含真实个人信息。

## 3. 功能与目录说明

### 3.1 八个核心实验

| 编号 | 实验 | 知识点 | 教材章节（目录级映射） | 核心可调参数 |
| :--- | :--- | :--- | :--- | :--- |
| M1 | 静态测试与代码审查 | 逐行标注缺陷并与人工基线比对 | 第7章 7.1–7.5 | 代码版本 · 审查范围 · 标注类型 · 规则集 · 严重度门槛 |
| M2 | 等价类划分 | 类覆盖率 vs 缺陷检出能力 | 第8章 8.1.1 | 被测字段 · 划分粒度 · 取样策略 · 是否含无效类 · 注入缺陷 |

| M6 | 白盒测试与覆盖分析 | 五种准则的分母 | 第8章 8.4 | 覆盖准则 · 用例库 · 被测版本 · 自动补齐预算 |

每个实验都具备：学习目标、认知堵点、理论要点、前置与边界、参数调节区、实时可视化反馈、结论验证区、证据沉淀按钮、重置与导出。

### 3.2 顶部导航页签与交互设计

- **总览导图**：全局进度环 + 交互式 8 关学习路线图 + 8 张卡通直达卡片 + 折叠「统一被测物速查」抽屉。
- **第 1–8 关单舞台游乐场**：每关采用「顶部控制条 + 高级调节抽屉 + 动画可视化舞台 + 大白话教练 + 明细抽屉」单舞台结构，内置 `动手玩` / `随堂测` / `一句话秘诀` 三连页签，以及「记为过关档案 / 重置」快捷动作。
- **随堂挑战**：覆盖第 1–11 章的 **48 道题**（28 单选 + 10 多选 + 10 填空），支持按章节、题型、难度、只看错题与“只刷前5题”筛选，作答后即刻展开逐项大白话拆解。
- **档案与地图**：汇总各关打卡/过关档案，支持 JSON 导入导出、一键重置，并附《软件质量保证与测试：原理技术与实践》章节速查地图。

### 3.3 目录结构

```
index.html                 ← 交付主作品与团队共享单文件（双击可用，由 build.mjs 生成）
README.md
src/                       ← 开发用源文件
  core/                    ← 纯计算，无 DOM；浏览器与 Node 共用同一份
    spec.js                ← 业务规格 v1.2（单一事实来源）+ 被测实现 + 缺陷变异
    equivalence.js         ← M2 等价类
    boundary.js            ← M3 边界值
    decision.js            ← M4 决策表引擎
    fsm.js                 ← M5 状态机
    whitebox.js            ← M6 代码解析 / 覆盖率 / CFG / 路径枚举
    regression.js          ← M7 用例套件与流水线
    quality.js             ← M8 风险模型与门禁
    staticreview.js        ← M1 代码清单、基线、规则库
    knowledge.js           ← 知识图谱数据
    quiz.js                ← 48 题多题型题库、逐项解析与判分引擎
  ui/                      ← util / graph / shell（路由、外壳、题库、证据库）
  modules/                 ← m1–m8 实验模块
  styles.css  template.html
build/build.mjs            ← 拼接为单文件 index.html / dist/index.html 并做静态校验
tests/                     ← Node 单测（80 项）+ 浏览器实机测试（不是运行依赖）
```

**关键工程约定**：`src/core/*.js` 用 UMD 包裹，浏览器挂到 `window.QT`，Node 端直接 `require`。
因此 `tests/` 测的就是作品运行时使用的同一份逻辑，不存在“另写一份实现来通过测试”。

## 6. 约 5 分钟体验路线

1. **0:00–0:40** 打开 `index.html`，在「总览导图」查看闯关路线图，展开底部抽屉速览所有实验共用的「培训报名算费系统」业务规则。
2. **0:40–2:00** 进入 **第 2 关「等价分区」**，点击不同颜色的“测试球”体验正常落桶、越界拦截与缺陷爆破，再点橙色/青色 **「⚡ 一键试组合坑 (D4)」** 揪出单字段测不出的复合折扣缺陷。
3. **2:00–3:00** 在第 2 关切换到 `随堂测` 页签做一题单选或填空，然后点击右上角 **「记为过关档案」**。
4. **3:00–4:00** 切换到 **第 7 关「质检流水线」**：默认 `v1.2-rc1` 因核心冒烟测试失败亮红灯拦截（哪怕总通过率 93.3%），切换 `v1.0` 即刻变绿放行。
5. **4:00–5:00** 来到 **第 8 关「发布门禁」**：点击「载入演示包」体验“先猜后揭晓”，拖动「修复工时」滑块实时观察风险体温下降与五盏放行红绿灯变化。

## 7. 计算真实性说明（简版）

1. **单一事实来源**：`src/core/spec.js` 定义业务规格，8 个实验全部引用它，不存在两套互相矛盾的规则。
2. **预期值独立推导**：`feeSpec()` 是按规格表写的参考判定函数，被测实现 `_calcFee()` 另写一份；
   两者由 4800 组输入的网格测试校验一致（`tests/spec.test.js` SPEC-01）。
3. **缺陷是真实变异**：4 个缺陷会真的改变函数输出，不是“开关式假失败”。
   每个缺陷在测试网格上都有实际的检出计数（SPEC-06）。
4. **覆盖率有明确分母**：块数 18、判定 14、条件 24、路径 33，全部写在界面上。
5. **分母为 0 时显示 “—”**，不显示 0% 或 100%（`pct()` 返回 `null`）。
6. **回归耗时是实测**：`performance.now()` 计时，单位毫秒。
7. **风险模型公式公开**：R = 100 × (wD·Dn + wG·G + wE·E + wF·F)，权重、标定点、KLOC 均为教学设定。

## 8. 已知限制

1. **静态审查的规则库只有 8 条**，模拟“配置了少量规则的检查器”，不是通用静态分析器；会产生误报与漏报。
2. **人工基线带主观性**：代码中真实存在但基线未收录的问题会被计为“误报”。这是度量口径的局限，不是 bug。
3. **被测函数是整数域单入口**，不含并发、浮点精度、时区、网络等真实工程因素。
4. **状态机 11 状态 / 14 迁移为本项目定义**，不含超时迁移与并发冲突；路径覆盖因存在回边而不设分母。
5. **白盒实验的条件均为独立布尔变量**，不涉及短路求值；真实项目需额外声明口径。
6. **回归套件 30 条为教学规模**，不能代表真实项目的回归充分性；“教学流水线”未连接任何真实 CI 平台。
7. **M8 风险模型未经真实项目校准**，不能用于横向比较或行业基准。
8. **未做多浏览器兼容性测试**，仅在 Chrome 上实测。
9. 教材章节只做**目录级映射**，不复述教材正文、不引用页码。

```bash
# 浏览器实机测试（需要本机 Chrome 与 npm i 安装 puppeteer-core）
npm run test:browser
# 或分项运行：
node tests/browser/smoke.mjs        # 13 个视图渲染 + 控制台错误 + 离线 + 尺寸
node tests/browser/structure.mjs    # 20 项结构契约（参数/章节/占位/注入/图谱）
node tests/browser/interaction.mjs  # 25 项关键交互与多题型自测
node tests/browser/persistence.mjs  # 8 项存储/导出/导入/重置/降级
```

> 协作提示：每次修改 `src/` 后请顺手执行 `node build/build.mjs`，连同更新后的 `index.html` 一并提交，保证所有成员拉取后即可直接双击打开最新版单文件页面。

### 重新部署到 Cloudflare（可选）

```bash
node build/build.mjs      # 同时写出 index.html 与 dist/index.html
wrangler deploy           # 读取 wrangler.toml，上传 dist/ 并刷新自定义域名
```

`wrangler.toml` 里只发布 `dist/` 目录（即构建产物），源码、文档与测试不会进入 CDN。
自定义域名 `qa-lab.campusphere.ltd` 通过 Workers Custom Domain 绑定，DNS 记录与证书由 Cloudflare 自动签发。

浏览器测试依赖 `puppeteer-core`，已在 `package.json` 中列为 devDependency。
**交付目录中不含 `node_modules`**（避免几十 MB 的生成物混入作品）；如需运行浏览器测试，
先执行一次 `npm i`（需要网络），再按上面的命令运行。

`index.html` 本身**不依赖任何 npm 包**：它没有构建产物依赖、没有运行时依赖、没有外部请求。
